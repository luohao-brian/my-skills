# 报告格式

正文按“主模型的本期更新与当前关注 → 衍生与独立专项 → 媒体生态 → 本地开发”排列。每层再按任务分组，逐条覆盖 `groups` 中全部正式候选，每个仓库只出现一次。“基础与专项”“热门衍生与本地”“本周重点新发现”“ComfyUI”是采集入口，不直接决定正文位置。不得画模型生态图、拼接跨仓工作流，或从仓库名推断能力。

```markdown
# AI 开源模型观察｜YYYY-MM-DD — YYYY-MM-DD

本期：主模型 N，衍生与独立专项 N，媒体生态 N；本地训练候选 N。

## 一、主模型：本期更新与当前关注

### LLM/VLM

#### 1. 模型名称

- 背景与用途：用模型卡明确支持的一句话说明任务；不要从名称推断。
- 输入/输出：结构化输入 → 输出；只有模型卡证据时注明“模型卡”。
- 基座模型：仅在有可确认且有阅读价值的基座时给出模型链接；没有则省略。
- 权重文件：当前仓主权重或组件的实际文件大小、精度与完整分片数；可选文件注明备选。
- 规模：HF 权重参数量；继承值注明“继承原模型”。
- 热度：TrendingScore N · 下载 N · 点赞 N。
- 窗口信号：新发布 | 仓库更新；无仓库事件时写“关注原因：仍在 HF 热榜 | 本次采集到活跃衍生”。
- 更新摘要：只写本窗口提交能证明的实质变化；没有则省略。
- 时间：发布或仓库更新日期；仅因热榜或衍生生态收录的条目在“关注原因”后标查询日期。
- 链接：[Hugging Face](https://huggingface.co/...)

其他任务按 LLM/VLM、图像/视频生成、VLA 与机器人动作策略、TTS/ASR、Decision、音乐与歌曲生成、文本音效与环境声、视频 Foley、多模态音频、歌声转换与合成顺序使用相同的逐模型字段；无候选的小节省略。VLA 小节先列当前窗口的基座与具体本体策略，按模型卡写“图像/视频＋指令＋机器人状态 → 动作”或其真实接口；`robotics` pipeline_tag 只负责候选召回，不直接证明 VLA。动作适配基座须标“不是完整策略”。

已登记的 SmolVLA、X-VLA、π0.5、OpenVLA、GR00T、MolmoAct 等 VLA 与其他主模型同样按本期仓库事件、当前任务热榜和活跃衍生引用筛选，符合条件时直接列入本节；无当前信号时不单列静态参考。写模型卡确认的输入/输出、本体与开发入口、HF 参数量、主权重大小及当前热度。已证实的热门 VLA 衍生按任务放第二层。历史 `--date` 只使用窗口事件。不要把世界模型、机器人推理模型或仅带 `robotics` 标签的任意仓库混称 VLA。

## 二、衍生与独立专项模型

### LLM/VLM

#### 1. 模型名称

- 背景与用途：模型卡明确的任务；说明是完整模型、量化包、LoRA、编码器或其他组件。
- 基座模型：仅写 `canonical_model_trace` 可确认的模型链接；没有明确基座或存在多父冲突时省略。
- 输入/输出：结构化输入 → 输出；只有模型卡证据时注明“模型卡”。
- 权重文件：当前仓实际交付文件的大小、精度与备选关系；LoRA 注明需要基座。
- 规模：HF 权重参数量；继承值注明。
- 热度：TrendingScore N · 下载 N · 点赞 N。
- 窗口信号、时间、链接：同上。

其余按图像/视频生成、VLA 衍生与本地模型、TTS/ASR、Decision、音乐与歌曲生成、文本音效与环境声、视频 Foley、多模态音频、歌声转换与合成、其他/分类待核分节。独立小型专项模型没有可确认的原模型时，仍按任务列入本节。

## 三、媒体与 ComfyUI 生态

### 视频生成与控制

#### 1. 模型或仓库名称

- 它是什么：只写结构化任务、精确 tag 或当前模型卡明确说明的能力。
- 基座模型：经追溯确认且有阅读价值时写模型链接；没有则省略。
- 输入/输出：结构化字段；卡片补充须标来源。
- 下载与组件：主权重、控制网络、LoRA、编码器、VAE 或超分组件的单文件大小和备选关系。
- 可用示例：仅当模型卡或实际 workflow 内容能核实任务、必需输入、所用组件和输出时，用一句话说明能完成什么，并链接对应 workflow 或使用指南。只拿到 `workflow_files` 文件名时省略这一行；文件清单留在候选 JSON。
- 热度：TrendingScore N · 下载 N · 点赞 N。
- 窗口信号、时间、链接：同上。

其余按姿态/动作/分割等条件提取、角色/人脸替换与动画、超分/修复/清晰度及其他媒体组件分节。

## 四、本地训练候选

### SFT | 离线蒸馏 | RLVR | Decision 类型化 SFT | Decision 可验证奖励 | 文生视频 LoRA | 视频 IC-LoRA | 音效 LoRA | 音乐 LoRA

#### 1. 小模型 + 数据集

- 方法：SFT | 离线 response 蒸馏 | RLVR/GRPO | Decision 类型化 SFT | Decision RLVR | 文生视频 LoRA | 视频 IC-LoRA | 音效 LoRA | 音乐 LoRA。
- 学生/基座：精确模型 ID、HF 参数量、实际主权重文件大小；不把文件大小写成训练显存。
- 数据集：精确数据集 ID、config/split 或仓库 manifest、已核验列名、单条样本的输入和监督或奖励信号。视频列出目标与参考素材路径；音频列出实际 Audio 特征和文字列。
- 数据准备：媒体数据写明原始列如何变为训练器要求的文件布局；视频写明匹配的文本编码器和缓存条件。
- 工具：按这一组合的执行步骤列精确项目和组件，如 `SFTTrainer`、`LoraConfig`、`GRPOTrainer`、`accuracy_reward`；每项写负责的动作并链接官方文档。不展示无关的工具仓库提交。
- 本地起步：该组合的具体抽样、长度或帧桶、LoRA 或奖励函数路径；官方显存仅按原适用模式引用，明确哪些资源指标尚需本机实测。
- 资源说明：本节导语交代本机峰值显存与吞吐的实测情况，不在每项重复。
- 链接：模型、数据集、训练方法的一手来源。

本节读取 `groups.development.opportunities`，持续核验登记的训练组合，不受 7 天更新窗口限制。模型、数据集、必需列及对应媒体素材证据不齐时不成稿。视频大模型可不提供 HF 结构化参数量，但必须有官方训练 checkpoint 文件和训练器资源说明；其文件大小仍不是显存。工具仓库的日常提交不展示；`groups.development.tools` 和 `.datasets` 留在 JSON 供变化审计。旧发布日期不能写成“本周新发现”。
```

## 分层与分类

- 第一层收模型发布方的独立主模型或基础模型，且候选资料明确其任务。依据发布方仓库、结构化 `base_model`、当前模型卡和权重性质判断；“无结构化父模型”本身不证明原创主模型。主模型可以从 `flagship`、`local` 或 `notable_discoveries` 任一入口发现。每个任务小节先呈现该任务的主模型；没有候选时省略空小节。
- 第二层收已证实衍生、量化、蒸馏、LoRA、微调，以及没有可验证 `canonical_model` 的小型独立专项模型。TTS/ASR、说话人分段、OCR 等专项模型不要因无 canonical 而漏掉。子类别按任务和输入输出分，不按“热门衍生”“重点新发现”等采集入口分。
- 第三层收有 ComfyUI 运行证据或明确媒体控制、提取、替换、动画、超分等组件证据的候选；即使仓库也有基础模型血缘，仍只在此出现一次。视频生成基础模型可在第一层，配套的 ComfyUI 打包、控制网络、LoRA、节点权重在此层。只写候选本身的证据，不推导不同仓库之间的可运行连接。
- 分类先用结构化任务、输入输出、`metadata.role`；若模型卡明确与采集 `role` 冲突，按卡片任务归类，冲突留在候选 JSON。证据不足时放“其他/分类待核”。`text-to-audio` 和 `video-to-audio` 只表示方向，不证明歌曲、Foley 或同步能力。

## 每项的可读字段

- `模型` 链接到候选 HF 仓库。`窗口信号` 显示 published、repository-updated 或当前热门及日期；`lastModified` 只证明仓库更新，不写成模型版本发布。具体更新仅按 `change_evidence.commits` 写；README、文档和宽泛上传不能推导能力升级。
- 基座模型只展示 `canonical_model_trace` 能确认、且有阅读价值的模型链接。自指且没有父路径、缺少证据、分叉或多父冲突时省略该字段。`root_model`、逐跳证据、原登记声明和一致性保留在候选 JSON。 音频模型卡若明确把标作 `base_model` 的仓库用作文本编码器等子组件，正文按实际组件用途说明，不称音频生成基座。
- 输入与输出优先取 `metadata.modalities`。结构化字段缺失、但当前模型卡明确写出两端时，可写“模型卡：输入 → 输出”；两类证据都缺失时省略该字段。结构化方向与卡片冲突时按可核实的卡片任务写，冲突留在候选 JSON。
- 参数量只取 HF 结构化 `metadata.scale.parameters`，写“HF 权重参数量”；`inherited=true` 标“继承原模型”，不当作当前 LoRA 文件参数量、激活参数量或整个系统的规模。
- 权重大小取 `deployment_profile.artifact_options` 中具明确字节数的模型主组件或当前仓实际交付的 LoRA、ControlNet、编码器、upscaler 等组件，使用十进制 GB/MB，并标组件与精度。同一索引的多个分片求和且须 `complete=true`；不同精度、不同步数和其他互斥版本只列代表性的备选档位，绝不相加。组件包写“主网络文件”，不称“完整运行包”；LoRA 写“LoRA 文件，需基座”；只有编码器时写“编码器文件”。`bytes=0` 或没有仓库文件证据写“未取得”。仓库总字节数、权重参数量都不能替代文件大小；文件大小不能写成显存。
- 热度压缩为 `T<TrendingScore> · 下载<downloads> · 赞<likes>`，只列实际存在的值。下载为 0 时如实写 0；没有跨日快照不写“上升”。热度和评测不可互为因果说明。
- 下载计数为 0、但已有明显点赞或热榜排名时，先核对 HF 列表/详情 API 和仓库文件。HF 下载统计依赖特定查询文件；若仓库缺少可计数的根目录配置或权重入口，保留原始 0 并标“HF 计数 0，统计口径可能不覆盖此仓”，附 HF 下载统计文档，不解释为实际无人下载。此时突出可证实的全局/任务热榜排名和点赞；不得把 TrendingScore 当下载量或推算实际下载数。
- 热度突出的主模型还要写一条“关注点”：从发布方公告或模型卡挑 1–2 个具体、可核对的发布事实，说明读者为什么值得查看该模型，例如新架构、开放的训练阶段、上下文长度、已公开的评测或后训练入口。标明来源与评测归属。除非有直接证据，不把这些事实写成 TrendingScore 的确定成因；下载与点赞仅是当前观察值。
- 本期无仓库更新、但因当前热榜、衍生引用或已登记音频专项模型的站内关注被纳入的原模型，写“关注依据：当前热榜排名/点赞，或本次采集到 N 个明确引用该模型的衍生仓，其中 M 个仍热门”，并给出至多 3 个代表衍生仓链接。引用数标“本次采集到”，不能写成 HF 全站总数。单次快照只写“当前”；音频模型只有点赞证据时写“当前站内关注”，不写“仍在热榜”；已登记模型若同时覆盖文本音效、视频音效与音乐，可列“多任务音频参照”，照实写低热度指标；跨日快照确有正增量时才写“热度上升”。这类模型归入原任务类别，不另设采集类章节。
- 可选的模型卡评测仅在对象、条件、数值与限制均有证据时写一两句，注明“模型卡报告”；不同卡片分数不直接横比。论文、架构、精度、媒体分辨率、帧率、工作流文件只在候选有对应证据且确有阅读价值时写。
- `comfyui_integration.topology_source=capability-template` 不进正文。实际 `workflow_files` 只证明仓库交付了文件，不单独成为报告卖点；同一仓库有多个文件时按可核实的任务用途归纳，不按路径排序截取前三个。说明用途须来自模型卡、配套指南或 workflow 节点/连线，不能从文件名猜。媒体能力只用 `media_customization.signals`、结构化任务或模型卡明确描述；未在当前环境运行的 workflow 不写成已验证可用。

没有候选时保留总标题，并写“本时间窗口内没有符合条件的候选”。不为补齐栏目引用窗口外基线模型。
