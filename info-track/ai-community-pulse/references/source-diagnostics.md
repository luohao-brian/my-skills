# 来源覆盖与热力图

来源分析回答“固定频道是否稳定产生有用候选”，不把候选条数解释成平台热度或来源质量。不同平台的固定频道数、单频道读取上限和榜单周期不同，绝对候选数不能直接横向排名。

## 分析顺序

1. 先看 `sources.<source>.ok`、`error` 和 `warning`，区分采集失败与正常低产。
2. 对单一来源计算 `selected / count`，判断当前固定入口的主题命中率；只在该来源内部解释，不跨平台比较。
3. 使用 `topics` 检查四类主题覆盖，对照 `channels_configured` 与 `channels_with_candidates` 检查候选是否集中在少数频道。
4. 合并同一事件、同一产品或高度相似标题后，再统计独立话题数。多个教程、转述或推广围绕同一发布只算一个话题信号，但保留相互独立的原始链接。
5. 连续多个采集窗口都为零或只产生同一事件的入口，才判定为需要调整的弱入口；单次窗口为零只写“本窗口无命中”。

## 热力图合同

- 主矩阵使用“主题 × 来源”，每格展示去重候选数；同时在列头标注该来源的 `deduplicated` 样本量。
- 色深在每个来源列内归一化，表达该来源本期的主题结构，不把不同列的色深解释成跨平台强弱。
- 另列来源状态、`selected / count`、`channels_with_candidates / channels_configured` 和缺失主题；不得输出“平台贡献排名”或“最大社区来源”。
- 样本量少于 5 时标注“小样本”，不得据此断言来源弱。采集失败的列使用失败状态，不绘制为零热度。
- 报告正文中的热点必须以合并后的独立话题为单位；候选量只用于覆盖诊断，不能替代话题综合。
