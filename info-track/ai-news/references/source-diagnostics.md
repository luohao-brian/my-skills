# 来源覆盖与热力图

AI 新闻来源分析回答“固定来源在窗口内覆盖了哪些栏目与事件”，不按候选绝对数量评价媒体质量或影响力。媒体、聚合简报和厂商官方来源具有不同发布节奏，必须按 `source_role` 分层解释。

Hex 2077 日报不列入默认固定来源。当前适配器只给条目写入日报日期，未取得逐条发布时间；实采样本中部分标题省略事件主体，无法可靠满足 72 小时边界和跨来源归并。可单独用于找线索，核对原始链接后再录入候选。

## 分析顺序

1. 先看 `ok`、`error`、`raw` 和 `window_candidates`，区分抓取失败、解析过滤和正常低产。
2. `window_candidates / raw` 只用于检查同一来源适配器在本窗口的有效率，不跨来源比较。
3. 先用“规范化 URL + 标题”合并精确重复，再按可核对的同一原文链接或规范化后相同的标题归并；其他相似标题和摘要由审核者确认后显式合并。仅 URL 相同不能合并聚合条目，因为聚合日报中的多条不同新闻可能共享一个落地页。不同媒体对同一事件的独立报道保留为该事件的多个来源，不重复计算事件数。
   AIHOT 的 `original_url` 与原文来源命中时是同一条信息链；AIHOT 不额外增加独立报道来源数。
4. 按本次简报实际出现的栏目生成“栏目 × 来源”矩阵；候选临时分类须标注为暂分，不能当作已核验主题。没有来源归属字段的旧候选不能进入矩阵。
5. 单次窗口无候选只写“本窗口无命中”；只有连续多个窗口为空、解析失败或有效率显著异常时，才建议调整入口。

## 热力图合同

- 主矩阵使用“栏目 × 来源”，每格是该来源在该栏目中的独立事件数；列头同时标注 `window_candidates` 和合并后的独立事件样本量。
- 色深在每个来源列内归一化，只表达该来源的栏目结构。`media`、`aggregator`、`official` 分区展示，不生成跨角色的来源贡献排名。
- 另列运行状态、`window_candidates / raw`、精确重复行数、共享落地页行数和跨来源事件覆盖数。
- 同一事件被多个来源覆盖时可显示“来源数”，但不能把来源数解释为事实正确率；摘要仍需核对原始报道。
- 样本量少于 5 时标注“小样本”；采集失败使用失败状态，不绘制为零热度。
- 禁止输出“最大新闻源”“最强媒体”“影响力排名”或把聚合器转载量当成独立新闻量。
